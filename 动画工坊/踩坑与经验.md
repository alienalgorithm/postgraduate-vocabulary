# 踩坑与经验

做《如何真正学好英语》时踩过的坑，每条一句问题、一句解法。来源：五版工作流各代理的结论、主会话记录、作品目录和 tools/ 下的各份说明。已经由程序挡住的，写明是哪个程序。

## 画面和引擎

| 问题 | 解法 |
|---|---|
| 截图时页面里 loading="lazy" 的图片在画面外永远不加载，截图一直等着卡住 | 要截图的页面里图片一律 eager 加载；场景里放图只用 `u.image`、`u.sequence`、`u.preload`，seek 会等它们加载完（CSS background-image 要先 `u.preload`） |
| 原曲第 18 小节只有 2 拍，引擎 musicGrid 按“每 3 拍一条小节线”推，39.342 秒以后全部错一拍，still、render、test 都报 s05 以后“离小节线 0.625 秒”（误报） | 小节线一律用 map.json 的 bars；场景按分镜里的精确时刻卡点，不用 `u.bar()`、`barPulse`；分镜检查 check_storyboard.py 用真实 bars，是对的。引擎还没改（应在有 `music.bars` 时直接用它） |
| 静帧 QA 报字小于 40px、字重叠（s05 标题两行入场时重叠 6px）、字出画 | 每个字的进出时刻都出静帧看；字至少 40px；分组错开；anim-check 的 stills_qa.py 每次推送都查 |
| 旋转的字母被字号检查误报为太小 | 字母用方形字母盒再旋转 |
| 背景里装饰用的小字（窗户里的词、星空里的词）达不到 40px | 放到 canvas 或 WebGL 层，QA 不读那两层；要让人读的字仍然至少 40px，靠静帧人工看 |
| ScrambleText 的乱码依赖上一帧画了什么，乱序 seek 画面不同 | 引擎给它打了补丁，乱码只由时间决定 |
| 渐变填充的文字拆成单个字后渐变坏了 | 引擎给每个字分一段渐变 |
| canvas 的 imageSmoothing、lineJoin 等设置跨帧残留，16.3 秒以后的帧取决于之前画过哪些帧 | 每帧重设 canvas 设置，每次画用 save 和 restore |
| canvas 的 shadowBlur 在不同页面上画得不一样 | 用预先画好的发光贴图代替 shadowBlur |
| CSS backdrop-filter 加 translate3d 镜头，在分块边界差到 57/255 | 去掉；毛玻璃效果画在 canvas 上 |
| 卡片重复 seek 后状态不同 | 卡片设 force3D |
| GSAP stagger 做的退场比字幕的 out 时间晚 | 改成显式的逐字延迟 |
| 闪光层和隐藏的 three.js 画布留着前几帧的残影 | 引擎每帧清掉 |
| 液体溶解的河流在 4K 下出现圆环和硬边色块 | 河流改画成柔和的填充带 |
| 场景文件缺失时，render 在最后一块报“ffmpeg exited early”，看不出原因 | 那是缺场景；草稿可以加 `--force`，正式出片不加（缺场景是质量问题，该停） |
| 别的作者的场景还没写，test.js 整体打印 FAIL | 看本场那几个时刻的结果；缺的场景只在它出现的时间段里算错误 |
| three.js 在 4K 下每帧多约 260 毫秒 | 只用在名场面；更重时用实例化网格、`THREE.Points`、关抗锯齿，或 canvas、CSS 3D 假装三维；最后的退路 `--nothree` |
| 全屏 CSS blur 或 SVG 滤镜在 4K 下很慢 | 用预先模糊的 canvas 层 |
| 用 JPEG 截帧想提速，实际没快（802 对 779 毫秒） | 保持 PNG |
| 本机 4K 整片约 2 小时以上，还占满 CPU、抢别的工作流 | 4K 一律推到 GitHub 分 20 段并行出；本机只出静帧和几秒的 1080p 片段 |
| 本机磁盘只剩几 GB，4K 帧图存盘会撑满 | 帧用管道直接送进 ffmpeg，不存帧图；临时文件放仓库外的临时目录，用完删大文件 |
| 没有 music/energy.json 时引擎把能量当成恒定 0.5，画面明显不同（PSNR 只有 23 到 38 dB） | energy.json 是数据不是音频，明文进仓库，出片必需 |
| 本机装了别的系统字体，缺字时会悄悄回落，看不出来 | 字体全在作品 fonts/；CI 把 fontconfig 指向空配置；写了字体里没有的字两边都不对，要换字或补字体（tools/fonts.md） |
| 本机 CPU 和 GitHub 运行器不同（AVX-512 对 AVX2），像素最低位可能不同 | 参考静帧比 PSNR，阈值整帧 40 dB、最差小块 28 dB；2026-11-19 第一次在运行器上实测：6 张参考图和本机逐字节相同（PSNR 99 dB），机器差异没有出现；以后真不一致，从 stills-all 取运行器出的图换进 qa/ref/ |
| 升级 playwright 就换了 Chromium，画面可能变 | playwright 固定 1.63.0；升级后跑 update_refs.sh 重出参考图 |
| 本机测试 test.js 会往作品目录的 stills/ 写图 | 不要在别人正在写的工作目录里跑；stills/ 被 .gitignore 挡住 |

## 配乐

| 问题 | 解法 |
|---|---|
| 仓库公开，版权音乐明文进仓库会招来 DMCA，整个仓库可能被下架 | 原曲和剪辑成品只提交 openssl 加密的 .enc；.gitignore 挡住明文音频（只放行 music/backup/、music/cc0/）；package_music.sh 最后逐个核对明文没进仓库 |
| 起初想用免版权音乐：许可五花八门，pixabay 有反爬用不了，会话网络默认连不上音乐网站 | 只用 CC0 或公共领域，CC-BY 只作备选并署名，NC、ND、许可不明的不用；每首记下载页和许可原文；为会话另建只放行几个音乐网站的网络环境 |
| 自己合成配乐不够好，用户要现成音乐 | 改用现成音乐；后来用户取得《Cornfield Chase》授权，原来选的 CC0 曲子 Epic Vista 改作备用配乐 |
| 一开始按原曲长度定片长 | 片长由内容定；配乐截段、循环、加小节去贴场景 |
| Epic Vista 原曲 200 Hz 以下左右声道反相，手机单声道外放时低音抵消（前奏少 7.7 dB） | 200 Hz 以下折叠成同相；以后每首都查左右相关和单声道相加的损失 |
| energy.json 的 hits 大多是噪声（351 个，均匀散在拍、八分、十六分上），画面每秒乱闪 1.7 次 | hits 只取换和弦的强拍和结构性时刻；急停放在 events（kind stop），不闪 |
| 限幅器在平滑后又把增益夹到最小值，起音变成瞬间跳变，爆发后 124 毫秒出现比原曲高 12 dB 的高频尖峰；剪辑师自己的检查只和原曲全局最大值比，漏掉了 | 去掉那一步夹取，起音是 8 毫秒平滑斜坡；对抗式质检逐位置和原曲比（scorelib.limiter 是修好的版本） |
| 原曲开头有前一轨留下的低频余音，抬高增益后听得见 | 开头加 1.2 秒升余弦淡入 |
| 原曲开头比高潮低约 26 LU，手机外放几乎听不见 | 安静段落用宏观增益整体抬高，余弦缓变；爆发前后的落差保留 |
| 从高潮往回跳会掉约 3 dB；原曲 83.717 秒以后往回跳低音突然消失 | 高潮只放在最后一次经过 |
| 在 G 和弦中间接回，音色变化听得出 | 接口挪到换和弦处（循环 9 到 5 代替 10 到 6） |
| 急停之后直接接开头的轻渐入，音量突然掉 10 dB，像被剪断 | 先让最后的 G 在 5 拍里渐弱 9 dB，再从同样的音量渐入 |
| 结尾在 G 上淡出，和声悬着 | 多加 2 小节落在 F 上，一拍后两小节淡出 |
| analysis.md 写的解码命令（ffmpeg -ar 48000）是笔误，按它解码重建不能逐样本一致 | 原采样率解码成 float32，再用 soxr VHQ 重采样到 48 kHz（scorelib.decode） |
| 不同曲子自己的高频尖峰从 11 dB 到 50 dB 都有，咔哒检查用固定门限会误报 | check_score.py 的咔哒检查只和原曲比（要给 `--ref 原曲`） |
| analyze_track.py 对 Cornfield Chase 自动选成 127.9 BPM 4/4（倍数歧义） | 给 `--bpm 96 --meter 3`；不规则小节只提示“强拍相位不一致区间”，要人确认 |
| 说 111.842 秒是“全曲最满的一刻”不准确：之后三小节 K 加权响度还在升 | 111.842 是高潮落点，恍然大悟放在这里；画面要继续加强到急停 117.467 |
| 剪辑师和质检都听不到声音 | 每个接口做数值检查（采样跳变、咔哒、凹陷鼓包、频谱变化、相位）加频谱图；对抗式质检 |
| 加密带随机盐，每次重新加密都会产生无意义的 git 改动 | package_music.sh 先用当前密钥解开旧文件，逐样本一致就不重新加密 |
| GitHub 运行器默认 Python 3.12，浮点结果可能和本机差最后几位 | anim-music 用 setup-python 指定 3.13，依赖固定在 requirements.txt；重建不一致时 rebuild_score.py --compare 报最大差值 |

## 故事和文字

| 问题 | 解法 |
|---|---|
| 画面夸大：遗忘曲线那场字母掉光、“一周后真的记得掉到很低” | 遗忘曲线不归零，只剩 ı 和暗到 30% 的光点；反复读一周后仍约 40%，写“掉了一大半”“掉下一大截” |
| 两个出处同时在屏上，看起来像后一个出处的结论 | 合成一个出处块；同一时刻只有一个出处 |
| 字停留时间不够读完 | 阅读时间公式 max(1.6, 0.6 + 字数 / 6) 秒，check_storyboard.py 逐条查；重排时字只许变长 |
| 星图里每拍出现一处相遇，字来不及读 | 改成一拍半一处（每条至少停 2.4 秒、同屏最多 3 条），和 3/4 拍形成二对三的错位，像心跳加快 |
| s07 退回冷蓝，和“逐步升温”矛盾 | 压暗不降温：亮度表示记得多少，色温是温度计，温度计不倒退 |
| 说“你已经遇见它十几次”，但数漏了一处 | 改动任何出现 evidence 的地方，都要重数（必须在 11 到 19 次之间），检查脚本核对 |
| 屏幕文字里出现破折号或国别、身份类字样 | text_rules.py 每次推送都查（连转义写法也查）；文档里写到时只写“BANNED 清单”，不写原词 |
| 引擎的示例场景 demo.js 词表里有一个禁用英文词 | new_film.sh 不复制 demo.js |
| 作品目录里几份内部规则文件（BRIEF.md、EVIDENCE.md 等）以规则形式写了禁用字样 | 仓库公开，任何文件里都不许有这些字样：同步时 tools/clean_words.py 自动改写（说明文字换成“清单见 BANNED”，程序词表换成 \u 转义，行为不变）；anim-check 每次推送用 clean_words.py --check 查整个 动画工坊/ |

## 流程和 GitHub

| 问题 | 解法 |
|---|---|
| 需求中途改了四次（自己合成配乐、免版权音乐、Cornfield Chase、片长由内容定） | 旧版归档（story/v1_epicvista、scenes_v1），新分镜用 derived_from 复用旧场景代码 |
| 全部场景建完再审，返工慢 | 流水线：每场建完立刻对抗式审查 |
| 工作目录里有大量本机绝对路径 | engine_patches/apply.sh 把引擎里的去掉；同步后自动重套，幂等 |
| 本机没有 rsync，apt 也装不上 | sync_from_workspace.sh 用 tar 整目录替换，效果和 rsync -a --delete 一样 |
| 仓库是稀疏检出，新文件 git add 不进去；checkout 或 pull 后本机工作区可能删掉 assets 里的图片 | 用 `git add --sparse`；图片没了就再跑一次 sync_from_workspace.sh（GitHub 上自己稀疏检出 动画工坊，不受影响） |
| 仓库里有大量大文件，Actions 全量检出很慢 | 工作流一律 sparse-checkout（只取 动画工坊 和 .github）加 `filter: blob:none` |
| 会话里 gh 命令行的令牌无效；actions/secrets 接口被代理禁止 | Release 由 Actions 里的 GITHUB_TOKEN 发；仓库密钥由仓库主人在网页上手动加；不绕过 |
| Run workflow 按钮只在默认分支 main 上的工作流才有 | 用改 渲染请求.json 推送的方式触发 |
| 发 Release 会把仓库首页的资料 Release 挤下去 | `--latest=false` |
| 中文附件文件名在下载和命令行里容易出问题 | 附件文件名只用英文字母（how-to-learn-english_4k.mp4） |
| 浏览器偶发崩溃会让一段渲染失败 | render_shard.sh 自动重试一次；还不行就 Re-run failed jobs，只重跑那一段 |
| 缺密钥会让出片停下 | decrypt_music.sh 永远以 0 退出：主配乐、备用配乐、无声依次退，并写明原因 |
| 本机下载 actionlint 被权限分类器拒绝 | 不绕过；YAML 用解析和交叉核对代替，第一次推送后以 GitHub 实际解析为准 |
| 主会话太长会被压缩，细节丢失 | 方法、规矩、坑都写进仓库文档和程序，不靠会话记忆 |
