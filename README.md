第19篇以270词最终精进锁定稿为准。最终上限审查进一步修复了警报显示语序与五次警报计数，明确雷达开关配置和交流相位失配共同产生虚假计数请求，并把执行程序写成按优先级调度、在无空闲工作区时重启并从记录检查点恢复。遥测判断和警报边界也被收紧：警报提供可供行动的信息，却不会自动命令中止。结尾以“系统可以过载而不崩溃”重新定义稳健性。

## 最终版本铁律

- 一旦某篇文章形成新的最终稿、最终精校稿或最终锁定稿，必须在同一次变更中同步权威数据、Markdown、网站、README、交接文档、入库记录和最终版本清单。
- 新最终稿一经进入主分支，旧稿立即失去权威性；旧内容只能留在Git历史中，不得继续留在活动数据文件、正式Markdown、网站入口或未合并分支中制造歧义。
- 只有从 `main` 回读确认新正文，并且全量校验成功后，才可以声称“已经存到云端”。
- `data/final-version-manifest.json` 保存每篇文章的完整内容指纹；`node scripts/final-version-guard.js` 会阻止旧稿、错误指标或未同步文件重新进入主分支。

完整规则见 [notes/最终版本铁律.md](notes/最终版本铁律.md)。

## 数据层与生成方式

当前权威数据层按以下顺序加载：

```text
data/articles.js      # 第01—07篇
data/article-08.js    # 第08篇
data/article-09.js    # 第09篇
data/article-10.js    # 第10篇
data/article-11.js    # 第11篇
data/article-12.js    # 第12篇
data/article-13.js    # 第13篇
data/article-14.js    # 第14篇
data/article-15.js    # 第15篇
data/article-16.js    # 第16篇
data/article-17.js    # 第17篇
data/article-18.js    # 第18篇
data/article-19.js    # 第19篇
data/article-20.js    # 第20篇
```

它们共同构成 `window.SITE.ARTICLES`。网站三个页面与Markdown生成脚本都加载同一数据层，因此不会出现“网页一版、Markdown另一版”。

生成与校验：

```bash
python3 scripts/build_markdown.py
```

脚本会：

- 生成／刷新 `articles/*.md`
- 校验英文加粗、中文对应括注和速查表数量
- 校验词数、密度和20%红线
- 检查文章编号、slug及跨篇精确重复

仓库还包含 `.github/workflows/validate-content.yml`，会在PR和主分支提交时执行同一套19篇全量校验，并检查数据脚本与网站入口。

## 硬性标准

| 项目 | 要求 |
|---|---|
| 英文词数 | **新文章优先240—270词，原则上不超过270词；既有锁定稿不追溯重改** |
| 重点词 | 恰好50个 |
| 密度 | ≤20% |
| 文体 | 《经济学人》风格科普社论 |
| 内容 | 人物、日期、数字或具体案例 |
| 中文 | 先自然表达，再建立加粗对应 |
| 结尾 | 提供新的理解框架，不只复述正文 |
| 事实 | 关键数据与叙事边界可追溯 |

铁律：

> 英文加粗的重点词，在中文译文中必须有对应的自然译法；中文译法同样加粗，并在后面附英文原样括注。
