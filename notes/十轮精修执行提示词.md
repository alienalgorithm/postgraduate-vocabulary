# 十轮精修 · 执行提示词

> 用法：在开头写明篇号，例如「按本提示词精修第21篇」，然后把本文件全文发出。

---

## 你要做的事

对指定的一篇文章，**完整跑完十轮精修**，一轮不落，跑到临界点为止。

**临界点的定义**：再动一处，就必须拿走另一样东西（论证力、中文可读性、词价、
史实准确、或某项硬指标）。到了这个位置停手，并写明是哪一样东西挡住了。

---

## 不许漏跑：用守门器，不靠自觉

流程由 `scripts/polish.py` 把关。它是状态机，不是清单。

```bash
python3 scripts/polish.py <篇号> status     # 进行到哪一轮、台账多少处待审
python3 scripts/polish.py <篇号> next       # 生成下一轮所需材料
python3 scripts/polish.py <篇号> done <轮> --note "改了…／没改…／因为…"
python3 scripts/polish.py <篇号> log <轮> --pos … --before … --after … --why …
```

**它强制三件事：**

1. **不许跳轮** —— `done 4` 在第1轮未完成时会被直接拒绝
2. **不许敷衍** —— `--note` 少于 30 字会被拒绝，必须写明「改了什么／什么没改／为什么」
3. **不许不记账** —— 每处改动都要 `log`，否则第八轮的回退审计无从做起

**每一轮的固定动作：**

```
polish.py <篇号> next          → 读材料，做判断
（有改动就）log ... 逐处记账
（改完后）inspector.py <篇号>   → 确认没为修一处而碰坏另一处
polish.py <篇号> done <轮> --note "..."
```

## 十轮各查什么

| 轮 | 层 | 核心问题 |
|---|---|---|
| 1 | 机器层 | 九层规则、审读任务书、preflight 的每一条，处置或写明保留理由 |
| 2 | 句序层 | 每句的回报在哪？隔两段的，是不是来早了 |
| 3 | 接缝层 | 四处段落接缝，后一句接不接得住前一句交出的东西 |
| 4 | 因果层 | 每个连接词真的成立吗；抽象有没有跑在具体前面；末两句是否都是格言 |
| 5 | 中文层 | 遮住英文单读中文——这是中国人会写的中文吗 |
| 6 | 词价层 | 50 个名额逐个问：考生学到这个词，值不值 |
| 7 | 母语者层 | 对标 Brown 说理散文实测档案；抽象主语、无施事被动、句长节奏 |
| 8 | **回退审计** | 台账逐行：这一改是真的更好，还是只是让告警消失了 |
| 9 | **整体冷读** | 放下清单通读，答三问 |
| 10 | 临界点判定 | 每个「没改」项，答出「改它要牺牲什么」 |

细则见 `notes/单篇精修提示词.md`，`polish.py` 每轮会把要点打在材料前面。

## 三条纪律，全程适用

**一 · 改之前先把真实文本读出来。**
用 node 从数据层取出该段的 en / zh 原文，再做替换，并用 `assert` 校验匹配。
**不要凭记忆构造匹配串**——本项目曾因此一次改坏三篇。

**二 · 每轮改完回跑 `inspector.py <篇号>`。**
约三分之一的新缺陷是修改时引入的。

**三 · 「没改」和「改了」同样要写理由。**
「没改」的理由就是临界点的证据。

---

## 第八、九轮为什么不能省

前七轮是分层打磨。**分层打磨有两个固有缺陷：**

**缺陷一：打磨本身会打磨坏。** 本项目实际发生过三次——
为消「结尾格言相邻」在五篇末段各硬插一句事实（其中一句还是重复的）；
一次 `re.sub` 未加 `count=1` 改坏了另一篇；
一个 fallback 静默写坏 98 条速查表释义而所有校验照常通过。
**第八轮就是为这个而设**：遮住理由，并排读改前改后，
选不出哪个更好的，就是中性改动，应当回退。

**缺陷二：每层都过，合起来仍可能是一篇没劲的文章。**
整体只能整体地读。**第九轮不能用清单代替**——
它只问三个问题：读到哪里卡了一下、哪句想再读一遍、明天还记得哪一句。

第九轮若发现问题，回到对应轮次去改，**然后重跑第八轮**。

---

## 关于「母语者觉得好得不能再好」

这是最终标准，但它不是第十一轮，**它是前十轮的结果**。

支撑它的七样东西，各自由哪一轮保证：

| | 轮次 |
|---|---|
| 有真反转，读者预期被证据推翻 | 选题时定，第九轮验证 |
| 每句把一个东西交给下一句 | 2、3、4 |
| 具体压过抽象：给数字不给形容词 | 4、7 |
| 主语是人和具体物 | 7 |
| 长短句交替，有呼吸 | 7 |
| 结尾给出能带走的命题，不是总结 | 4、9 |
| 没有一个词是凑数的 | 6 |

**任何一样塌了，母语者都只会觉得「还行」。**
而「哇」这个东西机器判不了——只有第九轮那次冷读能判。

## 最终交付

1. `notes/精修台账-<篇号>.md`：每处改动的改前／改后／理由／第八轮复核结论
2. 十轮各自的「改了什么 ／ 什么没改 ／ 为什么」
3. 第九轮冷读的三个答案
4. `python3 scripts/preflight.py` 全绿输出
5. 两句结论：
   - **这篇已到临界点，挡住它的是 ______**
   - **第八轮回退了 __ 处，因为它们只是消掉了告警**

---

## 推送前必须同步三处

任何一篇的 words / density 一改：

1. `data/*.js` 的 metrics
2. `scripts/final-version-guard.js` 里 README / 交接文档的行校验
3. `.github/workflows/validate-content.yml` 里的硬编码期望值 ← **本地跑不到**

`preflight.py` 会查第三处。**不要跳过**——本项目两次「本地全绿、CI 却红」都栽在这里。
