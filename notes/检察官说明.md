# 单词检察官 · 使用说明与能力边界

> v5 · 2026-08-15
> `scripts/inspector.py`（量化层）+ `tools/单词检察官v3.html`（正则层）

---

## 一、一句话

**检察官不判文章好坏，它让"写坏"变得困难、让"冲突"变得不可能、把需要人判断的地方全部标出来。**

---

## 二、能力边界（先说不能做什么）

我做过两轮全库相关性检验，试图让机器自动判定"文章质量"。**结论是做不到。**

第一轮在 17/12/19（范文）与 03/07（低分）之间，"反转词数量"看起来能分开——03 和 07 是 0，范文都 ≥1。

第二轮扩到全部 20 篇，信号消失：

| 候选特征 | 低分组均值 | 高分组均值 | 判定 |
|---|---|---|---|
| 反转词数量 | 1.5 | 1.9 | 无区分（第11、13篇也是0，却拿77/81） |
| 中段反转 | 0.8 | 1.0 | 无区分 |
| 末段新框架词 | 30.0 | 27.5 | **反向** |
| 句子接力率 | — | — | 范文第17篇仅7%，指标本身是错的 |
| be动词率 / 标题呼应 | — | — | 噪声 |

更根本的问题：拿来做相关性的"分数"本身就是检察官自己的规则算出来的，这是循环论证。

**所以 v5 明确放弃"质量分"，改称"合规分"**——它衡量硬约束达标程度，不衡量文章好坏。
论证力、反转、结尾升华这些，只在**提示层**给人工判断线索，权重为 0，不参与计分。

## 三、三种用法

### 1. 词池：写之前把冲突排除掉

```bash
python3 scripts/inspector.py --pool vent plume basalt symbiosis gut oasis
python3 scripts/inspector.py --pool candidates.txt --exclude 03    # 改写第03篇时不计它自己
```

逐词给出：Zipf 词频 → 词价等级 → 是否已被某篇占用。

```
vent        3.80  合格   ✗ 已被第 02 篇占用
plume       3.19  合格   ✓ 可用
return      5.19  白送   △ 可用，但价值低（考研生多半已掌握）
trophosome  0.00  生僻   △ 可用，但过于生僻（非考研词，仅在题材必需时用）
```

**这是"单词不冲突"的正解**：不是写完再查重返工，而是动笔前就只在可用池里选。
（缺陷库 PR-02 记录过：写完再查重，撞车就得重写整句。）

### 2. 起草台：入库前体检

```bash
python3 scripts/inspector.py --draft draft.md --exclude 03
```

草稿用空行分段，重点词用 `**双星号**`。一次给全：词数、重点词数、密度、段落数、
关键词分布与极差、各段词数、局部密度、篇内重复，再自动把 50 个词全部过一遍词池。

### 3. 全库审计

```bash
python3 scripts/inspector.py            # 合规排名
python3 scripts/inspector.py 03         # 单篇明细
python3 scripts/inspector.py --html     # 生成 tools/检察官报告.html
```

## 四、四个检查层

| 层 | 严重度 | 查什么 |
|---|---|---|
| **MET 指标** | 硬伤 | 词数 / 重点词数 / 密度 / metrics自洽 / 段落数 / 速查表条数 / 中英加粗逐段配对 |
| **VAL 词价** | 硬伤 | 白送词占比、专名内部加粗、篇内重复、**跨篇词元与表面形式冲突** |
| **BAL 均衡** | 硬伤+待核 | 各段关键词极差（硬）、局部密度上下限（待核）、残段、段落长短悬殊 |
| **STR 骨架** | 待核 | 无人名、段落无数字、结尾格言拥挤、前提晚于异常 |
| **JDG 提示** | 权重0 | 中段无转折、抽象名词作主语、正文出现评论性副词、代词开头需核指代 |

**局部密度是待核不是硬伤**——它是外形指标。范文第17篇 §3 就有 21.3%，
一段偏密本身不构成缺陷，只有和"短段塞满词"同时出现时才是（如第02篇旧稿 §4：38词塞10个词=26.3%）。

## 五、阈值怎么定的

以第17/12/19篇（结构最规整的三篇）为"不该报警"的基准反推：

| 参数 | 值 | 依据 |
|---|---|---|
| 白送词判定 | Zipf ≥ 5.0 | return 5.19 / support 5.53 / deep 5.05 确定白送；shield 4.30 / alpha 4.25 合格 |
| 边缘词 | Zipf 4.6—5.0 | 只计数，不判硬伤 |
| 生僻词 | Zipf < 2.5 | 题材必需时可用（fuselage 3.09、airworthiness 2.31 属此类） |
| 各段关键词极差 | ≤ 2 | 范文实测 0 |
| 单段局部密度 | 硬 24% / 提醒 22% | 范文最高 21.3% |
| 白送词容忍 | ≤ 6 个 | 第02篇旧稿曾达 20 个 |

**v4 的第一版把上限定成 20%，把范文第17篇都判成硬伤——那是误报，已修。**
凡是把范文判成不合格的阈值，都是阈值错了。

## 七、与 v2/v3 的关系

`tools/单词检察官v3.html` 是**正则规则引擎**，51 条规则，抓文字缺陷（搭配错配、指代断裂、
同义反复、编造史实）。它继续有效，是浏览器里粘贴单篇用的。

`scripts/inspector.py` 抓的是正则看不见的东西：分布、词价、跨篇冲突。
第02篇旧稿的 13·13·3·10·11 分布与 26.3% 局部密度，v3 一条都报不出来——这就是量化层存在的理由。

两者互补，都不替代人的判断。
