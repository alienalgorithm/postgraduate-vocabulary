# 单词检察官 · 使用说明与能力边界

> v8 · 2026-08-16
> `scripts/agent.py`（写作智能体）+ `scripts/inspector.py`（量化层）+ `tools/单词检察官v3.html`（正则层）

---

## 一、一句话

**检察官不判文章好坏，它让"写坏"变得困难、让"冲突"变得不可能、把需要人判断的地方全部标出来。**

---

## 二、能力边界（先说不能做什么）

我做过两轮全库相关性检验，试图让机器自动判定"文章质量"。**结论是做不到。**

第一轮在 17/12/19（范文）与 03/07（低分）之间，"反转词数量"看起来能分开——03 和 07 是 0，范文都 ≥1。

第二轮扩到全部 20 篇，信号消失：

| 候选特征 | 低分组均值 | 高分组均值 | 判定 |
|---|---|---|---|
| 反转词数量 | 1.5 | 1.9 | 无区分（第11、13篇也是0，却拿77/81） |
| 中段反转 | 0.8 | 1.0 | 无区分 |
| 末段新框架词 | 30.0 | 27.5 | **反向** |
| 句子接力率 | — | — | 范文第17篇仅7%，指标本身是错的 |
| be动词率 / 标题呼应 | — | — | 噪声 |

更根本的问题：拿来做相关性的"分数"本身就是检察官自己的规则算出来的，这是循环论证。

**所以 v5 明确放弃"质量分"，改称"合规分"**——它衡量硬约束达标程度，不衡量文章好坏。
论证力、反转、结尾升华这些，只在**提示层**给人工判断线索，权重为 0，不参与计分。

## 三、一条命令：起飞前检查

```bash
python3 scripts/preflight.py
```

它跑五步，第一步是 **33 条工具回归测试**——本会话修过十来个工具缺陷
（误报把范文判成不合格、漏报让几百条错误静默通过），全部靠偶然发现。
没有测试，同样的 bug 会再回来。

**规则：每修一个工具缺陷，就往 `scripts/test_tools.py` 加一条用例。**

现有用例锁住的缺陷：范文阈值、STR-01 句首人名、STR-02 拼写数词、
STR-03 事实句非格言、STR-04 描述性 instead、GLO-01 释义写成英文、
GLO-02 条目错位与不规则动词误报、ZH-02 中文词被拆、FACT-01 数字出处、
agent.kin 同族判定、VAL-01 词价阈值。

推送前跑这一个就够。它把 CI 里的每一步在本地复跑一遍，**包括本地跑不到的那一步**。

存在的理由：本会话出现过两次「本地全绿、CI 却红」。任何一篇的 words/density 一改，
**必须同步三处**，而第三处只在 CI 上执行：

1. `data/*.js` 的 metrics
2. `scripts/final-version-guard.js` 里 README / 交接文档的行校验
3. `.github/workflows/validate-content.yml` 里 16—20 篇的硬编码期望值 ← 本地跑不到

preflight 把第三处也查了。

## 四、审读任务书：机器出题，人来判断

```bash
python3 scripts/agent.py audit 13     # 单篇
python3 scripts/agent.py audit        # 全库
```

这是 v6 的核心新增。前面反复证明：**句序、因果、接缝这些决定「丝滑」的东西，
表层特征判不了**（两轮全库相关性检验，见 §2）。但机器能做另一件事——
**把「该在哪里做判断」精确指出来，并把上下文摆好**。机器不下结论，机器出题。

四类题：

| 题 | 问什么 | 抓到过什么 |
|---|---|---|
| **一 · 段落接缝** | 后一句是否承接前一句交给它的东西？ | 第15篇「电控对手赢了试验」→「科芬推动立法」缺一拍 |
| **二 · 因果连接词** | 前一句真的推得出这一句吗？ | 第13篇「基因从没动过；**所以**每一块色斑都是一只钟」推不出 |
| **三 · 抽象与具体的次序** | 一般性结论是否等事实说尽才出现？ | 第19、20篇结论跑在具体前面 |
| **四 · 逐句回报** | 这句的回报出现在哪里？隔两段才有，多半来得太早 | 第02篇「船上没有生物学家」该在 §3 而非 §1 |

**临界点判据**：改一处若要牺牲另一处（论证、中文、词价、指标），即为临界点，停手。

## 五、写作智能体（scripts/agent.py）

检察官是事后的。智能体是事前与事中的——它不判分，只做三件机器擅长而人做起来极慢的事。

### brief · 把研究材料变成可用词池

```bash
python3 scripts/agent.py brief notes.txt            # 新篇
python3 scripts/agent.py brief notes.txt --exclude 03   # 改写第03篇，不计它自己
```

喂进研究笔记，吐出四组词：

| 组 | 含义 |
|---|---|
| **可用高价值词** | 题材里出现过、Zipf 2.5—4.6、未被任何篇占用 —— 从这里挑满50个 |
| 题材必需的生僻词 | Zipf<2.5，非考研词，只在绕不开时用（airworthiness 2.31 属此类） |
| **必须避开** | 已被占用，**含同根**（return 用过则 returns/returned 一并排除） |
| 不要浪费名额 | Zipf≥5.0 的白送词与 4.6—5.0 的边缘词 |

专名（材料中从未以小写出现的词）自动剔除——Comet、Naples 不是可学的词。

实测：彗星客机的研究笔记 → 76 个可用高价值词、5 个题材必需生僻词、33 个冲突词。
**冲突在动笔前就被排除，而不是写完返工。**

### review · 把草稿变成按优先级排序的修改指令

```bash
python3 scripts/agent.py review draft.md
```

不给平铺的报错列表，给分四级、可依次执行的指令：

```
一、阻塞项（不修则不能入库）
  1. 与其他篇冲突（含同根）：confirmed→第17篇
二、结构（决定这篇能到什么水平）
  2. 关键词分布 9·11·12·11·7，极差 5。从 §3 移出 2 个到 §5，目标 10·10·10·10·10。
  3. §1 只有 35 词，是残段……
三、词价（决定教学价值）
  5. 白送词 7 个占用名额：station(5.01)、data(5.34)……
四、需人工判断（机器只能提示）
  13. 中段没有任何转折词。确认这是在论证而不是在编年。
```

注：**词干比对是智能体独有的**——`inspector.py` 只比对精确形式，
智能体的 review 抓出了第03篇 `confirmed` 与第17篇 `confirmation` 同根撞车。

### skeleton · 五段功能骨架

```bash
python3 scripts/agent.py skeleton
```

自第17/12/19篇反推的每段任务书：布景与装置 → 异常本身（连同为何反常）→
当时的解释为何不够 → 判别性证据 → 意义与升华。附范例。

## 六、检察官的三种用法

### 1. 词池：写之前把冲突排除掉

```bash
python3 scripts/inspector.py --pool vent plume basalt symbiosis gut oasis
python3 scripts/inspector.py --pool candidates.txt --exclude 03    # 改写第03篇时不计它自己
```

逐词给出：Zipf 词频 → 词价等级 → 是否已被某篇占用。

```
vent        3.80  合格   ✗ 已被第 02 篇占用
plume       3.19  合格   ✓ 可用
return      5.19  白送   △ 可用，但价值低（考研生多半已掌握）
trophosome  0.00  生僻   △ 可用，但过于生僻（非考研词，仅在题材必需时用）
```

**这是"单词不冲突"的正解**：不是写完再查重返工，而是动笔前就只在可用池里选。
（缺陷库 PR-02 记录过：写完再查重，撞车就得重写整句。）

### 2. 起草台：入库前体检

```bash
python3 scripts/inspector.py --draft draft.md --exclude 03
```

草稿用空行分段，重点词用 `**双星号**`。一次给全：词数、重点词数、密度、段落数、
关键词分布与极差、各段词数、局部密度、篇内重复，再自动把 50 个词全部过一遍词池。

### 3. 全库审计

```bash
python3 scripts/inspector.py            # 合规排名
python3 scripts/inspector.py 03         # 单篇明细
python3 scripts/inspector.py --html     # 生成 tools/检察官报告.html
```

## 七、六个检查层

| 层 | 严重度 | 查什么 |
|---|---|---|
| **MET 指标** | 硬伤 | 词数 / 重点词数 / 密度 / metrics自洽 / 段落数 / 中英加粗逐段配对 |
| **VAL 词价** | 硬伤 | 白送词占比、专名内部加粗、篇内重复、跨篇词元与表面形式冲突 |
| **BAL 均衡** | 硬伤+待核 | 各段关键词极差（硬）、局部密度、残段、段落长短悬殊 |
| **STR 骨架** | 待核 | 无人名、段落无数字、结尾格言拥挤、前提晚于异常 |
| **GLO 速查表** | 硬伤 | **释义必须是中文**、**条目与正文加粗一一对应**、词元宜为原形 |
| **ZH 中文** | 待核+提示 | **单字加粗需确认**、**一个中文词被拆成两个名额** |
| **SYN 句法** | 待核 | **spaCy 真解析**：抽象主语、被动过量、句长节奏、单句过长、邻句复述 |
| **FACT 史实** | 硬伤+待核 | **正文里的每个数字必须在 facts 中有出处** |
| **JDG 提示** | 权重0 | 中段无转折、抽象名词作主语、正文评论性副词、代词开头 |

**SYN 层（2026-08-16 加，v8）**：前七层全是正则与统计，这一层装了 spaCy 依存解析，
从「按字面猜」升级为「真读句子」。四项判据以范文实测为基准：

| 判据 | 阈值 | 依据 |
|---|---|---|
| 被动语态占比 | ≤15% | 范文多在 0—11%；**带 by 施事的被动不计入**（The circular was **signed** by Pickering 正要突出署名者不是她） |
| 抽象名词作主语 | 0 | 写作规范 §3.3；正则版只能匹配 The discovery… 这类固定开头，依存解析能认出任意位置的 nsubj |
| 句长标准差 | ≥4.5 | 低于此值节奏发闷 |
| 单句词数 | ≤34 | 一句只装一个意思 |
| 邻句实词重复 | ≤0.35 | 接力靠推进，不是复述同一个名词 |

上线即查出旧七层完全看不见的问题：第08、10、13篇被动语态达 19—20%；
**范文第17篇有三处抽象主语**（Rutherford's analysis / theory / The discovery），
全部把主语还给了人：「1911年卢瑟福提出」「卢瑟福做的不只是解释」「是三个人共同做成的」。

**FACT 层（2026-08-16 加，v7）**：正文改过几百次，数字最容易随改动飘走而无人察觉。
上线即查出 13 处正文数字在史实核对中查无出处（第20篇的 8.95 百万吨上限、
第16篇的 1220 公里内核半径、第06篇的 32 万倍放大、第18篇的十万分之一各向异性），
全部补齐来源。

**GLO 与 ZH 两层也是 2026-08-16 加的**，固化本会话发现的静默损坏：

- **GLO-01 释义写成英文（曾 98 处）**：重建速查表时 fallback 写入了英文原词。
  第08篇 50 条里有 10 条的「中文释义」其实是英文，而**所有校验都通过了**——
  脚本只查条数与唯一性，不查内容是不是中文。
- **GLO-02 条目与正文错位（曾 270 处）**：曾假设「速查表顺序 == 中文括注顺序」。
  但中英语序天然不同：`a **physician** who lived **nearby**` ↔
  `住在**附近**(nearby)的**内科医生**(physician)`。按位置配对整体串位。
- **ZH-01/02**：为对上英文而挤出的单字（**溶**、**等**、**围**），
  以及被拆成两个名额的中文词（**追**授、**骤**跌、**摇**手**轮**）。

**两条通用教训（已入缺陷库）**：
1. fallback 绝不能写入源语言内容——那会把「缺失」伪装成「已完成」，静默通过全部校验
2. 跨语言配对必须用显式键（括注里的英文词），不能用位置

| 层 | 严重度 | 查什么 |
|---|---|---|
| **MET 指标** | 硬伤 | 词数 / 重点词数 / 密度 / metrics自洽 / 段落数 / 速查表条数 / 中英加粗逐段配对 |
| **VAL 词价** | 硬伤 | 白送词占比、专名内部加粗、篇内重复、**跨篇词元与表面形式冲突** |
| **BAL 均衡** | 硬伤+待核 | 各段关键词极差（硬）、局部密度上下限（待核）、残段、段落长短悬殊 |
| **STR 骨架** | 待核 | 无人名、段落无数字、结尾格言拥挤、前提晚于异常 |
| **SYN 句法** | 待核 | **spaCy 真解析**：抽象主语、被动过量、句长节奏、单句过长、邻句复述 |
| **FACT 史实** | 硬伤+待核 | **正文里的每个数字必须在 facts 中有出处** |
| **JDG 提示** | 权重0 | 中段无转折、抽象名词作主语、正文出现评论性副词、代词开头需核指代 |

**局部密度是待核不是硬伤**——它是外形指标。范文第17篇 §3 就有 21.3%，
一段偏密本身不构成缺陷，只有和"短段塞满词"同时出现时才是（如第02篇旧稿 §4：38词塞10个词=26.3%）。

## 八、阈值怎么定的

以第17/12/19篇（结构最规整的三篇）为"不该报警"的基准反推：

| 参数 | 值 | 依据 |
|---|---|---|
| 白送词判定 | Zipf ≥ 5.0 | return 5.19 / support 5.53 / deep 5.05 确定白送；shield 4.30 / alpha 4.25 合格 |
| 边缘词 | Zipf 4.6—5.0 | 只计数，不判硬伤 |
| 生僻词 | Zipf < 2.5 | 题材必需时可用（fuselage 3.09、airworthiness 2.31 属此类） |
| 各段关键词极差 | ≤ 2 | 范文实测 0 |
| 单段局部密度 | 硬 24% / 提醒 22% | 范文最高 21.3% |
| 白送词容忍 | ≤ 6 个 | 第02篇旧稿曾达 20 个 |

**v4 的第一版把上限定成 20%，把范文第17篇都判成硬伤——那是误报，已修。**
凡是把范文判成不合格的阈值，都是阈值错了。

## 十、三层的分工

`tools/单词检察官v3.html` 是**正则规则引擎**，51 条规则，抓文字缺陷（搭配错配、指代断裂、
同义反复、编造史实）。它继续有效，是浏览器里粘贴单篇用的。

`scripts/inspector.py` 抓的是正则看不见的东西：分布、词价、跨篇冲突。
第02篇旧稿的 13·13·3·10·11 分布与 26.3% 局部密度，v3 一条都报不出来——这就是量化层存在的理由。

`scripts/agent.py` 是事前与事中的：让冲突不可能发生，让结构问题在入库前暴露，
并把每一处需要判断的地方精确标出。

三层都不替代人的判断。**反转够不够狠、结尾能不能迁移，仍然只能由人来定。**
智能体的价值不在于代替判断，而在于把所有可机械保证的事情机械地保证掉，
好让判断力全部用在真正需要它的地方。
