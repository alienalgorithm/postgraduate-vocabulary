# 听读页 · 黑板跟读

> 2026-09-04 立。用户给了一张黑板视频截图和一个离线 TTS 小程序（`say-en`，kokoro-onnx），要「能直接播放、合成音频来读文章」的网页，16:9。

## 是什么

`listen.html?a=01` —— 16:9 木框黑板，一句一句放英文朗读：

- **英文逐词高亮**，跟着音频走（时间轴来自 `say.word_times`，毫秒）
- **中英重点词同色**：英文里的 `**word**` 与中文里的 `**词**(word)` 配成对，六个色号轮转——这就是那张截图里 `content to` 与「满足于」同色的做法
- 中文黑板上不显示英文括注（括注只在下面的全文清单里）
- 连续播放 / 单句循环 / 0.75×—1.15× / 空格与左右键 / 点全文任意一句从那里开始

## 音频怎么来

`scripts/build_reader.py NN` —— 离线合成，不联网、无 API key：

```
python3 scripts/build_reader.py 01 --voice bf_emma --speed 0.95
```

音色：`bf_emma` 英音女 · `bm_george` 英音男 · `af_heart` 美音女 · `am_michael` 美音男。
需要 say-en 解压在 `/tmp/say/say-en`（`--say` 可改），模型 340 MB 自行下载。
产出 `reader/aNN.json` 与 `reader/audio/aNN-SS.m4a|.opus`。第01篇：18 句、91 秒、1.1 MB。

## 三处踩过的坑（都留了注释在代码里）

1. **中英句子不能按标点对齐。** 第01篇末段英文 5 句、中文 4 句（中文用分号并了两句），按标点对齐会整段退化成一句（实测 21.75 秒的一句）。
   **改按重点词对齐**：中文切在哪，由这句英文的重点词在中文里的落点决定——重点词是两边唯一严格对应的锚点。
   附带一条：找断句处要取**最近的**标点，不能按「。比；强」排优先级，否则一句会吞掉下一句的中文。
2. **音频格式。** 只出 opus → iOS Safari 放不出来；只出 m4a → 开源 Chromium 不含 AAC，本地根本验不了响没响。
   两种都出，**开局用真音频探一次**，能放 m4a 就全用 m4a（iOS 必须），否则全用 opus。
   `<source>` 多源回退不管用：实测 Chromium 停在 `networkState=3`，不往下试；每句「先失败再换源」事件顺序也绕不通。
3. **音频路径少了 `reader/` 前缀**，是 404，可 `currentSrc` 只看文件名完全看不出来——查了很久。相对路径要相对页面，不是相对 JSON。

## 照 say-en《踩过的坑》补上的（2026-09-04 读完完整版文档之后）

那份文档八条坑，有四条正戳中这里的做法：

| 坑 | 文档说什么 | 这边怎么办的 |
|---|---|---|
| 三·削波 / 七·元数据假象 | 「八项检查全过，可一次都没解码过，34 段削波」 | **每段生成后立刻 `say.inspect()` 解码**查削波/过轻/过短，结果连同 peak、rms 写进 `aNN.json` 的 `qc`；测试也照着查 |
| 四·时间轴越界 | 重新编码会改时长，末项要对着**编码后**的时长比 | 对 m4a 与 opus 各解码取时长，末项超了就截，**截完重新保证递增** |
| 一·单位 | 存成秒不报错，光标定死不动；判据：末项 ≥ 1000 | 加了这条判据（句长 >1.5 秒时） |
| 五·被 OOM 杀掉 | 长任务必须能断点续跑，没有任何报错就消失 | `--n` 限流 + 读旧 json 跳过已完成；70 篇约 1,200 段，反复跑同一条命令推进 |

另外把 opus 的写盘换成官方 `say.write()`，不再自己拼 ffmpeg 命令（m4a 官方不支持，仍自己编）。

实测第01篇 36 个文件：峰值 0.552—0.950（0.950 正是归一上限）、RMS 0.089—0.104、质检零问题。

## 金色高亮与视频（2026-09-04，用户指定）

- **重点词一律金色** `#f5c542`（对齐参考图二），六个色号仍在 CSS 里，全指向同一支金——将来要换回多色只改一行。
  木框与板色也跟着调亮（`--board:#0e6d69`、`--frame:#e0a75f`），英文用 Poppins Bold、中文用 Noto Sans SC。
- **`scripts/make_video.py NN` → `reader/aNN.mp4`**：1920×1080、25 fps、H.264 + AAC。
  一句一帧，帧时长＝该句**解码后**的时长＋句间停顿（默认 0.32 秒）；音频直接拼已合成好的 opus，
  **不重新合成**——重合成每次波形都有尾差（say-en《原理》第七节），拼旧文件才对得上。
  实测第01篇：97.05 秒、7.8 MB，画面累计与音轨时长差 **0.00 秒**。
- **`watch.html?a=01`**：网页里放这个 mp4，16:9，下面挂同一份中英清单，点句跳转（句子起点用与渲染同一份数算）。
- 黑板渐晕改用 numpy 算平滑径向衰减——早先拿嵌套矩形描边画，屏幕上是一圈同心方框，像靶子。
  木纹也改成低频噪声，比等距条纹自然。

## 意群成对（2026-09-04，用户要「不要上英下中两大块」，又两次要求「对得精准一些」）

**每一小段英文底下就跟着它自己的中文，段与段之间空一行。** 视频与网页同一排法。
拆分在 `build_reader.align_chunks`，写进 `aNN.json` 的 `chunks`。第01篇 18 句 → 35 段。

### 走过的两版

**第一版（错的）**：按英文标点切，再去中文里找地方下刀。
用户一眼看出问题：英文「In September 1854 a few streets of Soho,」是一整段，
中文却在「1854 年 9 月，」后面就有逗号——**中英标点根本不一样**，只用英文的标点，
「1854 年 9 月」就落不到「In September 1854」底下。

**第二版（现在这个）**：**两边同时出切点，动态规划找整体最优的对齐。**

- 中文候选切点＝每个标点之后；英文候选切点＝每个词之后。
- 每一段的代价：
  | 项 | 说明 |
  |---|---|
  | 长度占比不符 | 中英两边各算占全句的比例，差超过 3 个百分点才罚——用户看出来的错就是这一项 |
  | 锚点错位 | 这段英文里的重点词，它的中文括注必须落在这段中文里 |
  | 英文断在半路 | 不在标点处断罚 26；但**下一个词是冠词/连词/代词**这类开头词只罚 7（「In September 1854 \| a few streets…」本来就是自然停顿）；断在虚词后面（a/the/and/of）再加 34 |
  | 断在连词之前 | **奖励** −18，那是天然的意群边界 |
  | 段落过长过短 | 超过 13 词、少于 3 词都罚 |
- 每多切一段给 **−30** 的奖励，所以**能拆就拆**；拦错交给锚点项，不靠「不敢拆」来保准。

### 第三版：用户指出 §8 该拆没拆之后补的四条

「A brewery beside the pump lost nobody, / since the men were supplied with beer.」两边都在标点收尾、
锚点也对得上，本该拆开，却因为字数比差了 13 个百分点被并回去了。**长度占比压得太重，把更强的证据盖住了。**

| 补的判据 | 拦住的错 |
|---|---|
| 长度占比容差 3% → **10%**，只当兜底 | §8 该拆没拆 |
| **否定词两边要对上**（英 not/no/never… ↔ 中 不/没/无/未/非，排除「不过／不但」这类） | §16「the board accepted his advice, / not his conclusion.」中文是「不是他的结论，／只是他的建议；」——**顺序反的**，两段都没重点词，只有否定词看得出来 |
| **数字两边要对上**（一边有数字一边没有就罚） | §10「died on 2 September;」被划进上一段，可它的中文「9 月 2 日」在下一段 |
| 虚词惩罚**只在没有标点时**才算 | 「doubted it,」的 it 后面有逗号本就是断句处，罚它就会退而切成「…doubted」，把动词和宾语劈开 |
| 非标点处断开 26 → **60**；开头词例外 7 → **20**；断在连词前奖励 −18 → **−30** | 「and went house」「the dead drew」这类半截；§11「…bottle and died / the next day.」→「…bottle / and died the next day.」 |

第01篇 18 句 → 39 段，**逐句核对无错位**。

### 顺带修好的两处句级错位

- 「第二天也死了」跑到了下一句 → 锚点区间内若有句号就优先切句号。
- 「只是他的建议；」漏到下一句 → 候选标点不止一个时**按英文词数比例**挑，
  而且比例要算在**去掉括注的纯中文**上——括注 `(fading)` `(accepted)` 长短不一，
  按原始下标算会把目标位置带偏几十个字符。

## 对齐检查员（2026-09-04，用户要「一个专门检查这件事的机器人」）

`scripts/check_chunks.py NN` —— **每次 build_reader 生成完自动跑**，写 `notes/对齐检查-NN.md`，有 A 级退出码 1，preflight 不放行。

**设计原则：检查员不复用对齐算法的打分。** 算法优化的是它自己的代价函数，再拿同一套去查等于考生自己阅卷。
十条判据全部独立、全部可解释：

| 判据 | 级 | 抓的是今天哪次错 |
|---|---|---|
| 拼回去必须等于原句（英不丢词、中不丢字） | A | — |
| 跨段锚点顺序单调（重点词在英文第几段，括注就得在中文第几段） | A | — |
| 段内锚点数目相等、每个重点词的括注都在本段 | A | — |
| **否定词互换**：相邻两段一边英多中少、另一边英少中多 | A | `his advice, not his conclusion` ↔「不是结论，只是建议」语序反 |
| **数字两边对上**（月份名折成数字） | A | `2 September` 与「9 月 2 日」不在一段 |
| 长度占比差 >20% | A | 「1854 年 9 月」没落在 `In September 1854` 底下 |
| 英文以介词/连词/冠词收尾 | A | `and went house to` |
| 中文以「的/在/把/被/和…」收尾 | A | `John Snow,` 底下配「住在」 |
| 该拆没拆（英文有从句标点、中文有标点、却只一段） | B | `lost nobody,` 没拆 |
| 段内语序相反（中文定语前置） | C | 只提醒：这段不可再拆 |

单段「中多英少」的否定词只记 C——中文本来就常拿「不」译实义词（doubted→不信，wrong→不该），第一版把这个判成 A，现版误报了五处，改成只抓互换形态。

**自测**：`--selftest` 拿今天亲手抓出来的六种坏对齐喂它，六种全逮住；再拿对好的第 01 篇，零误报。锁进回归测试。

**它能保证什么、不能保证什么**：结构性的错全能逮到，而且是确定性的；**纯语义的配错——两段各自完整、锚点也对、只是意思配错了——规则逮不到**，这一层只有 `--llm`（五个独立模型实例各读一遍，需密钥）或真人能给。没有密钥时它会明说，不假装查过。

## 段距标准（2026-09-04，用户定：以后所有视频都照这个）

**段内贴紧，段间拉开——一眼看得出上下两组是分开的。**

| | 视频（占画面高） | 网页 |
|---|---|---|
| 段内（英文 → 它自己的中文） | 1.0% | 1–5 px |
| 段间（一组 → 下一组） | **6.2%** | 16–40 px |

段间距 ≈ 段内距的 6 倍。字号往下找放得下的档位时，两个距离按同一比例缩，**比例不变**。
锁在测试里：`make_video.py` 的 `gap_chunk` 必须 ≥ `gap_pair` 的 5 倍。

另修一处：重点词后面的标点（`**delivered**.`）原本被当成独立的词，画出来是「delivered .」；
现在紧贴前一个词——判据是**前一块不以空格结尾且这一块不以空格开头**（「a **widow**」中间有空格，不贴）。

## 字号与结尾缓冲（2026-09-04，用户指定）

- **字号由大往小搜，取放得下的最大号**（从 2.4 档往下每步 0.02）。早先是从 1.0 起往下缩——
  短句也只能用 1.0，屏幕大片空着。安全区＝黑板内沿再往里收（左右 4.5% W、上下 5.5% H），文字永远不贴木框；
  单个词若超宽（长单词、长中文块）这一档直接判不合格，避免半个词挂到框上。
- **结尾留 1.5 秒静音缓冲**（`--tail`，默认 1.5）：最后一句读完，画面还在，声音没了，再结束。
  实测末段音量 −91 dB（纯静音），读完前 −19.9 dB；视频 98.55 秒＝各句解码时长＋停顿＋1.5，差 0.00 秒。
