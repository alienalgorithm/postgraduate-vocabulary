# 听读页 · 黑板跟读

> 2026-09-04 立。用户给了一张黑板视频截图和一个离线 TTS 小程序（`say-en`，kokoro-onnx），要「能直接播放、合成音频来读文章」的网页，16:9。

## 是什么

`listen.html?a=01` —— 16:9 木框黑板，一句一句放英文朗读：

- **英文逐词高亮**，跟着音频走（时间轴来自 `say.word_times`，毫秒）
- **中英重点词同色**：英文里的 `**word**` 与中文里的 `**词**(word)` 配成对，六个色号轮转——这就是那张截图里 `content to` 与「满足于」同色的做法
- 中文黑板上不显示英文括注（括注只在下面的全文清单里）
- 连续播放 / 单句循环 / 0.75×—1.15× / 空格与左右键 / 点全文任意一句从那里开始

## 音频怎么来

`scripts/build_reader.py NN` —— 离线合成，不联网、无 API key：

```
python3 scripts/build_reader.py 01 --voice bf_emma --speed 0.95
```

音色：`bf_emma` 英音女 · `bm_george` 英音男 · `af_heart` 美音女 · `am_michael` 美音男。
需要 say-en 解压在 `/tmp/say/say-en`（`--say` 可改），模型 340 MB 自行下载。
产出 `reader/aNN.json` 与 `reader/audio/aNN-SS.m4a|.opus`。第01篇：18 句、91 秒、1.1 MB。

## 三处踩过的坑（都留了注释在代码里）

1. **中英句子不能按标点对齐。** 第01篇末段英文 5 句、中文 4 句（中文用分号并了两句），按标点对齐会整段退化成一句（实测 21.75 秒的一句）。
   **改按重点词对齐**：中文切在哪，由这句英文的重点词在中文里的落点决定——重点词是两边唯一严格对应的锚点。
   附带一条：找断句处要取**最近的**标点，不能按「。比；强」排优先级，否则一句会吞掉下一句的中文。
2. **音频格式。** 只出 opus → iOS Safari 放不出来；只出 m4a → 开源 Chromium 不含 AAC，本地根本验不了响没响。
   两种都出，**开局用真音频探一次**，能放 m4a 就全用 m4a（iOS 必须），否则全用 opus。
   `<source>` 多源回退不管用：实测 Chromium 停在 `networkState=3`，不往下试；每句「先失败再换源」事件顺序也绕不通。
3. **音频路径少了 `reader/` 前缀**，是 404，可 `currentSrc` 只看文件名完全看不出来——查了很久。相对路径要相对页面，不是相对 JSON。

## 照 say-en《踩过的坑》补上的（2026-09-04 读完完整版文档之后）

那份文档八条坑，有四条正戳中这里的做法：

| 坑 | 文档说什么 | 这边怎么办的 |
|---|---|---|
| 三·削波 / 七·元数据假象 | 「八项检查全过，可一次都没解码过，34 段削波」 | **每段生成后立刻 `say.inspect()` 解码**查削波/过轻/过短，结果连同 peak、rms 写进 `aNN.json` 的 `qc`；测试也照着查 |
| 四·时间轴越界 | 重新编码会改时长，末项要对着**编码后**的时长比 | 对 m4a 与 opus 各解码取时长，末项超了就截，**截完重新保证递增** |
| 一·单位 | 存成秒不报错，光标定死不动；判据：末项 ≥ 1000 | 加了这条判据（句长 >1.5 秒时） |
| 五·被 OOM 杀掉 | 长任务必须能断点续跑，没有任何报错就消失 | `--n` 限流 + 读旧 json 跳过已完成；70 篇约 1,200 段，反复跑同一条命令推进 |

另外把 opus 的写盘换成官方 `say.write()`，不再自己拼 ffmpeg 命令（m4a 官方不支持，仍自己编）。

实测第01篇 36 个文件：峰值 0.552—0.950（0.950 正是归一上限）、RMS 0.089—0.104、质检零问题。
