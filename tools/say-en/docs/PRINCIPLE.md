# 原理：它到底怎么把字变成声音

这份文档解释三件事：
**语音合成怎么工作**、**逐词时间轴怎么算出来**、**质量三条为什么是那三条**。

不需要机器学习背景也能读完。

---

## 一、从字到声音，中间隔着什么

人念一句话，声带震动产生气压波，传到耳朵。
录下来就是一串数字 —— 每秒采样两万四千次，每次记一个介于 −1 和 1 之间的数。

```
"Hello"  →  [0.00, 0.02, -0.05, 0.13, 0.21, ... ]   共约 24000 × 1.2 = 28800 个数
```

**合成器要做的，就是从「Hello」这五个字母，算出这两万八千个数。**

中间隔着三道坎：

### 第一道：字母不等于读音

`read` 可能读 /riːd/ 也可能读 /red/。
`ough` 在 through、though、tough、cough 里读音全不同。

所以第一步是**字素转音素**（grapheme to phoneme）：

```
"Hello there"  →  /həˈloʊ ðɛr/
```

kokoro-onnx 内部用 `misaki` 这个库做这一步，它带一本发音词典，
词典里没有的词才退回规则推测。

### 第二道：音素不等于时长

同一个音素，在句首和句尾时长不同，重读和轻读也不同。
「Hello **there**」和「**Hello** there」，两个词的长短会反过来。

模型在这一步预测每个音素持续多久、音高怎么走。
这也是为什么合成出来的句子听着有语调，而不是一个字一个字蹦。

### 第三道：音素加时长，才能生成波形

有了「哪些音、各多长、音高怎么走」，声码器把它变成真正的波形。

Kokoro 把这三步合在一个模型里，输入文字与音色，直接输出波形。
82M 参数，跑在 CPU 上，一句话一到三秒。

## 二、四种音色是怎么回事

`voices-v1.0.bin` 里装的不是四段录音，而是**四组音色向量**。

可以这样理解：模型学会了「怎么说话」这件事本身，
而音色向量告诉它「用谁的嗓子说」。

```
文字  ──┐
        ├──→  模型  ──→  波形
音色向量 ┘
```

换一个向量，同一句话就换一个人念，语调结构不变。
所以四种音色的时长会有差别（男声通常慢一点），但断句位置基本一致。

实测同一句：

```
bf_emma      3.05s
bm_george    3.78s      ← 英音男声最慢
af_heart     3.13s
am_michael   3.62s
```

## 三、逐词时间轴：不用模型，用能量

做跟读高亮，需要知道**每个词从第几毫秒开始**。

模型不直接给这个。有两条路：

### 笨办法：按词数等分

```python
每词时长 = 总时长 / 词数
第 i 个词的起点 = i × 每词时长
```

**这个办法不能用。** 因为词长差别极大：

```
"a"                约 0.08 秒
"characteristics"  约 0.75 秒
```

等分的话，长词还没念完光标就跑了，短词念完了光标还没动。

### 本程序用的办法：找静音

念一句话，词与词之间会有极短的停顿 —— 气流中断，音量掉下去。
**把音量画成曲线，那些低谷就是词界。**

具体做法：

```
1  把波形切成 10 毫秒一帧，算每帧的平均音量
      24000 采样率 ÷ 100 = 240 个采样点一帧

2  平滑一下（相邻五帧取平均）
      不平滑的话单帧噪声会被当成停顿

3  低于平均音量 35% 的帧，标记为「静音」

4  连续两帧以上的静音段，算作一个候选词界
      记下它的中点位置和长度

5  按长度排序，取最长的 n−1 个（n 是词数）
      停顿越长，越可能是真正的词界

6  排序、去重、保证严格递增
```

代码在 `say.py` 的 `word_times()`。

### 为什么取「最长的 n−1 个」

一句 n 个词，需要 n−1 个分界点。
候选的静音段往往多于这个数（句中的辅音也会造成短暂的低谷），
所以按长度排序，取最明显的那几个。

**这个办法不完美** —— 连读的地方（"kind of"、"want to"）没有停顿，
会被切在稍微偏后的位置。但对跟读高亮来说完全够用：
光标落在正确的词上，或者慢半拍落到下一个词，读者是察觉不到的。

要更准的话得上强制对齐（forced alignment），
但那需要另一个模型，成本高出一个数量级。

## 四、质量三条为什么是那三条

这三条不是凭空定的，是从真实事故里长出来的。
完整故事见 `PITFALLS.md`，这里只讲原理。

### ① 峰值不超过 0.95

波形的取值范围是 −1 到 1。
超出这个范围的部分会被**削平**（clipping），听感上是刺耳的失真。

```
正常        ╱╲    ╱╲
           ╱  ╲  ╱  ╲

削波      ▔▔▔▔  ▔▔▔▔     ← 波峰被削平了
         ╱    ╲╱    ╲
```

模型输出偶尔会顶到 1.0，尤其是重读的音节。
所以合成后先看峰值，超过 0.95 就整体缩放：

```python
if peak > 0.95:
    wav = wav / peak * 0.95
```

**为什么留 0.05 的余量**：opus 是有损编码，
编码过程本身可能让某些采样点略微超过原值。留一点头是保险。

### ② 时间轴存毫秒

这条纯粹是接口约定，但它坑过人。

前端判断「现在该高亮第几个词」时，通常这么写：

```javascript
var ms = audioEl.currentTime * 1000;      // currentTime 的单位是秒
while (i + 1 < times.length && times[i+1] <= ms) i++;
```

`currentTime` 是秒，乘 1000 变毫秒。
所以 `times` 里也必须是毫秒。

**存成秒会怎样**：`times` 里全是 0.5、1.2 这样的小数，
而 `ms` 是 500、1200 —— 循环第一次比较就跳到最后一项，
光标定在句末不动。

**而且不报任何错。** 音频照常播放，控制台干干净净。
只有盯着光标看才能发现它没在动。

判据：一句话读完至少一秒,所以时间轴末项必然 ≥ 1000。
末项小于 1000 就说明存成秒了。

### ③ 时间轴末项不超出音频时长

末项是**最后一个词的起点**，不是音频结束点。
音频末尾还有那个词本身的时长加尾音，所以：

```
末项  <  音频总时长        正常
末项  >  音频总时长        错误 —— 最后几个词永远高亮不到
```

裁剪静音、重新编码之后，时长会略微变化，这时要回头校正时间轴。

## 五、静音裁边为什么留 60 毫秒

模型输出的首尾常带一小段静音（几十到几百毫秒不等）。

**不裁**：句与句之间停顿过长，连着播像卡了一下。
**裁光**：听着像被剪断，尤其是以爆破音开头的句子（p、t、k），
起音前那个短暂的闭塞期被裁掉，音就发闷。

所以裁到有声部分，再往两边各留 60 毫秒：

```python
thr = abs(wav).max() * 0.02          # 阈值取峰值的 2%
idx = (abs(wav) > thr).nonzero()[0]  # 有声区间
pad = SR * 60 // 1000                # 60 毫秒的采样点数
wav = wav[max(0, idx[0]-pad) : idx[-1]+pad]
```

60 这个数是试出来的：30 太紧，100 又能听出停顿。

## 六、为什么用 opus 而不是 mp3

```
              同等听感下的体积      浏览器支持
opus          最小（约 48 kbps）    全部现代浏览器
mp3           约 128 kbps          全部
wav           无损，约 10 倍大      全部
```

语音在 48 kbps 的 opus 下已经听不出损失，
而同样听感的 mp3 要 128 kbps —— 体积差近三倍。

一篇文章四百段音频，opus 约 20 MB，mp3 要 55 MB。

**要无损就加 `--format wav`**，比如需要再做后期处理时。

## 七、为什么两次合成结果不完全一样

同一模型、同一输入、同一音色，重跑一次波形不会逐位相同。

原因是浮点运算的顺序在不同 CPU、不同线程调度下会有细微差别，
神经网络层层放大之后，输出就有了尾差。

实测同一句重合成：

```
              新合成      旧的
时长          10.560     10.325     差 2.3%
峰值           0.761      0.695
RMS           0.0897     0.0885     差 1.4%
时间轴项数         30         30      一致
```

**听感上没有区别**，三项质量指标都一样。

如果你需要完全可复现的结果，唯一的办法是把音频文件本身存起来，
而不是每次重新合成 —— 这也是 IELTS 阅读库把 4000 多段音频
直接提交进仓库的原因。

## 八、整条流水线

```
文字
 │
 ├─ 1  字素转音素        misaki（模型内部）
 │
 ├─ 2  预测时长与音高     Kokoro 模型
 │
 ├─ 3  生成波形          声码器（模型内部）
 │
 ├─ 4  静音裁边          say.py  _trim()        留 60ms 气口
 │
 ├─ 5  峰值归一          say.py  synth()        超 0.95 就缩放
 │
 ├─ 6  算逐词时间轴       say.py  word_times()   能量包络找静音
 │
 ├─ 7  编码存盘          ffmpeg → opus 48kbps
 │
 └─ 8  质量检查          say.py  inspect()      削波/过轻/过短
```

第 1–3 步在模型里，第 4–8 步是本程序做的。
